# F1 Race Car — Vitruvius V-SUM Case Study

A Vitruvius case study that keeps a **generic race car model** consistent with two
**propulsion-specific models**, without merging them.

| Model | Scope | Branch |
|---|---|---|
| `racecar` | Generic vehicle: chassis, axles, wheels, propulsion slot. Shared by both case studies. | shared |
| `combustionracecar` | Engine, fuel tank, exhaust. | `racecar-combustionV2` |
| `electricalracecar` | Motor, battery, inverter. | `racecar-electric` |

When the generic model changes, Vitruvius automatically repairs the propulsion-specific model.
The two metamodels never reference each other — they are linked at runtime through the
**correspondence model**.

## Getting started

Requires **JDK 21+**.

```bash
chmod +x mvnw      # once: mvnw was committed without the executable bit
./mvnw install
```

> **Do not run `clean`.** EMF code generation is not wired into the Maven build — the
> `exec-maven-plugin` that runs `model/workflow/generate.mwe2` is commented out in `model/pom.xml`.
> `clean` deletes `model/target/generated-sources/ecore`, and Maven will not recreate it.
> Reactions code *is* generated by Maven, so only the EMF part is affected.

### Common commands

| Command | Purpose |
|---|---|
| `./mvnw install` | Build everything and run all tests |
| `./mvnw -pl vsum -am test` | Run only the V-SUM tests |
| `./mvnw -pl model,consistency -am install` | Rebuild metamodels and reactions only |

If Maven cannot resolve `kit.sdq.kastel.vitruvius:case-study:pom`, run the full reactor once
(`./mvnw install` without `-pl`) so the parent POM is installed locally.

### After changing an `.ecore`

Code generation happens in Eclipse, not in Maven:

1. Edit the `.ecore`
2. `.genmodel` → right click → **Reload...**
3. `.genmodel` → right click → **Generate Model Code**
4. Project → **Maven → Update Project** (Alt+F5)

## Project structure

| Folder | Contents |
|---|---|
| `model/` | Metamodels (`.ecore`) and code generation config (`.genmodel`) |
| `consistency/` | Consistency rules in the Reactions DSL (`.reactions`) |
| `viewtype/` | View type definitions |
| `vsum/` | V-SUM setup, runnable example, and tests |
| `docs/` | Case study documentation |

## Running the interactive example

The tests build a V-SUM in a throwaway `@TempDir`. To get **persistent files you can inspect**,
run the example instead:

```
vsum/src/main/java/.../CombustionVSUMExample.java
→ right click → Run As → Java Application
```

Optional arguments: `--reset`, `--vehicle-id=RC-042`, `--name=My Car`, `--rated-power=610.0`,
`--total-mass=798.0`

It walks through create → update → delete in one run and writes the resulting XMI files to
`vsum/target/vsum-example-run/`, where you can open them in a text editor or the EMF tree editor.
